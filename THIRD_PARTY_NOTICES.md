# Third-party notices

This project is **AGPL-3.0-or-later** (`LICENSE`). It ships and bundles code
written by other people, and the licences below are theirs, not ours. Only the
three entries that need a decision are written out; everything else is
permissive and needs nothing beyond its own copyright notice, which stays inside
the package in `node_modules/`.

Generated by reading the `license` field of every direct dependency in
`package.json`, plus a scan of the whole installed tree for anything that is
not MIT/ISC/BSD/Apache (last run 2026-09-09). Re-check it after adding one:
`npm ls --all` and the package's own `package.json` are the authority, never
this file.

## p5.js (LGPL-2.1)

`p5` (1.x) is the only **copyleft** dependency, and it is bundled into the
frontend build so a `p5` visual can run in the browser sandbox. LGPL-2.1
requires that a user be able to replace the library with their own version.
That is satisfied here by the shape of the project rather than by a special
mechanism: the whole application is AGPL, the source is the repository you are
reading, and `npm install` + `npm run build` rebuilds the bundle against any p5
you put in `node_modules/p5`.

The version is pinned to the 1.x line on purpose: 2.x changed the API the
sandbox and the visual-authoring prompts are written against.

## JSZip (dual MIT / GPL-3.0-or-later, taken under MIT)

`jszip` is offered under `(MIT OR GPL-3.0-or-later)`. **This project takes it
under the MIT half.** It is used for reading and writing `.apkg` archives
(Anki import and export). Nothing here relies on the GPL option, and choosing
MIT keeps that dependency permissive.

## DOMPurify (dual MPL-2.0 / Apache-2.0, taken under Apache-2.0)

`dompurify` is not a direct dependency: `mermaid` pulls it in, and it lands in
the browser build because mermaid renders there. It is offered under
`(MPL-2.0 OR Apache-2.0)` and **this project takes it under Apache-2.0**, the
same election made for `jszip` above. Nothing here relies on the MPL option.

## Everything else

Every other direct dependency is MIT, ISC, BSD-2-Clause, BSD-3-Clause or
Apache-2.0, all permissive and all compatible with AGPL-3.0-or-later. Two
transitive packages declare no licence in `package.json` (`khroma`, which
carries an MIT `license` file, and `buffers`, which carries neither); both are
tiny and neither is a reason for a decision here. Notable direct ones by
licence:

- **Apache-2.0**: `pdfjs-dist`, `pdf-parse`, `tesseract.js`, `typescript`
- **BSD**: `vega-embed` (3-clause), `mammoth` (2-clause)
- **ISC**: `lucide-react`
- **MIT OR Apache-2.0**: `sqlite-vec` (taken under MIT)
- **MIT**: everything remaining, including `react`, `express`,
  `better-sqlite3`, `@napi-rs/canvas`, `mermaid`, `katex`, `ts-fsrs`,
  `zustand`, `vite` and `tailwindcss`

## Fonts, models and data

The interface draws with the reader's system fonts. The one font family in the
build is KaTeX's (`KaTeX_*.woff2` under `dist/assets/`), which arrives with the
`katex` package and is covered by its MIT licence (Khan Academy). No other font
is vendored. The language model is whichever endpoint the reader configures;
it is not shipped, not downloaded by the app, and not covered by this file.
